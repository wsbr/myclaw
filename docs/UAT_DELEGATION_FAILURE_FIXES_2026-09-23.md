# UAT 委派失败信息与供应商尝试记录修复（2026-09-23）

本次修复来自会话 `01a0c8a0-e4b6-7c2e-bee2-300ea706bb86` 的三个已确认问题：子 Agent 失败后未向调用方交付已取得的检索证据；断流后账本缺少供应商请求标识；SDK 默认重试可能造成实际请求次数与 ProviderAttempt 不一致。

## 最终行为

- 失败结算保留原错误和 `failed` 状态，额外返回已成功搜索、抓取的来源和正文摘录。结构化部分成果通过 Chat/Plan Tool continuation 交付；Group 使用原定向接收权限交付可读消息。只读取同一身份、Run、目标 Work 和 Agent 的成功原生检索工具记录，核对冻结工具合同及执行状态；限制 12 个来源、24 KiB，并明确未完成及外部内容非指令。坏时间戳、非法 Unicode 等来源数据逐条跳过，保留正常证据；辅助展示错误不阻断失败结算，数据库异常仍走原事务处理。
- 收到响应头时立即用短事务保存请求 ID，断流错误再保存标识来源和 completion/message ID。元数据不算 payload；真实请求 ID 优先，只有缺失时才使用带来源标记的响应体 ID。每个重试独立记录，未收到或未提供的标识无法补造。
- OpenAI-compatible 和 Anthropic SDK 均设为 `max_retries=0`。现有 ModelAdapter 管理生成请求重试，每次尝试单独落账，避免 SDK 隐式请求。

本次不改变“已收到部分输出后不透明重试”、流完整性判定、工具执行或正式交付的现有门槛。不回填旧会话的部分成果或缺失请求 ID，不调用真实付费模型，不修改工具绑定、工具版本和数据库结构。检索证据提取是已授权工具结果的返回处理，不是平台通用提示词或新能力注入。
