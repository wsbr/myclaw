# UAT 模型输入与能力边界修复 — 2026-09-22

本轮修复由运行 `01a0c84b-8bae-7eb3-b497-c87700c137c4` 暴露的问题展开：Agent 仅绑定文件与发布工具，却因平台通用提示词尝试调用 `web_search`。该调用已被执行层拒绝；缺口在模型输入的能力描述。随后审计还确认了模型扩展参数覆盖请求、Skill 提示与权限不一致、定时 schema 回注以及内容可见性问题。

## 最终行为

- 平台通用规则保留权限、证据和数据可信边界；不再对所有 Agent 要求 Web 检索。工具操作指导声明所需能力，由每轮实际呈现的工具集合决定是否注入。Web 使用量明确标注 Runner 启动时快照，执行限额仍由机器检查。
- 冻结 AgentVersion、原始 ToolVersion 和绑定保持不变。已知旧内置文案通过展示投影移除对未绑定工具的无条件推荐，新的注册版本使用修正后的文案。展示文案与 schema 都进入呈现 hash。
- 每次模型请求、目录搜索、搜索结果幂等重放和续跑使用同一工具展示投影。运行中停用的工具被移出 schema 和操作指导。目录发现能力被停用时，其他仍有效的显式绑定工具直接展示，避免变得不可达。
- 定时运行中 `schedule_task` 仅允许 `operation=list`，保留 `status/limit` 筛选参数；修改操作不会因搜索或恢复重新出现，执行层继续拒绝递归修改。
- Skill 名称、说明、路径以结构化 assistant 数据呈现。只有存在可用读取工具时才注入加载指令；缺少读取能力时只使用目录信息。历史平台计划恢复通知兼容转换为不要求不可用工具的状态提示。
- 注册和 Provider Chat/Stream/Count 出口拒绝参数覆盖系统消息、工具和请求路由；现有 `extra_body.enable_thinking` 布尔配置保留。旧非法冻结模型配置返回明确的 `model_parameters_invalid`，不静默降级。
- 自动产物目录只包含当前 Agent 自己发布的产物或直接可见消息明确交付的附件，不再按 Session 全量注入其他 Agent 未共享的产物元数据。
- 同 Runner 复用记忆快照时重新校验状态、租户、用户、Agent 作用域和内容 hash；删除、被替代或不匹配的记录被排除，不自动补选新记忆。
- 普通 inline Tool 与 Runtime Tool 一样，在持久化执行前复查冻结绑定、合同及实时治理；停用、确认策略或风险规则变化不能沿用旧快照直接执行。

## 与后续工具组合包的关系

本轮保持单个 Tool 的显式绑定，不创建组合包，不自动增加绑定。未来组合包可以组织能力选择、说明和协作指导，但最终仍通过当前的装配、展示投影、条件式指导和执行授权边界。组合包不能成为绕过权限的另一条注入通道。
